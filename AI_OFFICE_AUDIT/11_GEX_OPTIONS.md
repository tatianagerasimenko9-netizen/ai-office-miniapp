# 11. GEX / Options — модуль контексту (специфікація 2.0)

**Статус коду зараз:** ABSENT. Немає gamma, walls, magnet, IV/RV, expirations, post-expiry regime.

Цей файл фіксує **роль модуля**, еталон короткої картки і як GEX складається з іншими шарами. Це не імплементація і не копія чужого поста.

## Роль (жорстко)

| Модуль | Що каже | Чого не каже |
|--------|---------|----------------|
| **GEX / options** | Характер руху: коридор, стіни, магніт, наскільки карта «густа» після експірації, IV vs RV | Напрямок LONG/SHORT |
| Heatmap | Де скупчення ліквідацій / можливий каскад | Напрямок сам по собі |
| Whales | Великий капітал (стакан / later on-chain) | Автоматичний вхід |
| Structure | Що робить ціна (BOS, sweep, reject) | Повний контекст ринку |
| Session | Коли вікно | Сетап |
| Setup Engine | Чи **складається** торгова ситуація з незалежних шарів | |
| Risk Engine | Entry / SL / TP / запас | |

**Заборонено:** «гамма впала → шортити».  
**Дозволено:** «стіна 90 000 + SHORT біля 89 800 → зона реакції; чекати confirm».

Не навалювати 50 індикаторів у чат. Кожен шар — своя посада. У користувача — коротка картина, не стаття.

## Що забирати з «такого» аналізу (схема полів)

Референс-кейс (п’ятнична експірація, цифри як **приклад схеми**, не live feed):

| Поле | Приклад |
|------|---------|
| `gex_total_usd` | 1.20B → 0.69B |
| `gex_change_pct` | −43% |
| `gamma_wall_upper` | 90 000 |
| `gamma_support_lower` | 84 000 |
| `corridor` | 84 000–90 000 |
| `corridor_width_note` | було ~1% (85k–84k), стало ~7% |
| `magnet_strike` | 90 000 |
| `magnet_strength` | слабкий (приклад: ~74M, ~6.6% від ціни) |
| `regime_boundary` | 74 279 (було 78 574) |
| `iv` | 25.0 |
| `rv` | 37.2 |
| `iv_rv_gap` | RV > IV на ~12 пунктів — опціони закладають спокійніше за факт |
| `next_major_expiry` | 2 жовтня (~28% ваги в прикладі) |
| `near_expiry_weight` | завтрашня дрібна (~12%) |
| `map_density` | `sparse` одразу після великої серії |
| `reliability` | `post_expiry_low` → рівні середини тижня інформативніші |

Джерело цих цифр у проді: **НЕ ВСТАНОВЛЕНО** (немає адаптера Deribit/GEX-провайдера в репо). Референс — зовнішній GEX-огляд + скріни TradingView як **зразок глибини контексту**, не як API.

## Картка в чат (еталон UX)

Не переказувати статтю. Один блок:

```text
🟡 BTC — GEX-контекст

Після великої експірації гамма: 1.20B → 0.69B (−43%).
Коридор: 84 000–90 000 (розширився).
Сильного магніта немає. Межа режиму: 74 279.
IV 25% / RV 37.2%. Наступна велика серія: 2 жовтня.
Карта зараз розріджена — рівні найближчих днів набиратимуться.

GEX напрямок не визначає. Це контекст для інших setup.
```

Подія `GEX_MAP_SPARSE` / `GEX_WALL` / `GEX_MAGNET_WEAK` пишеться в state. Повторювати статтю щогодини — заборонено. Оновлювати при: експірація, зміна wall/support, стрибок IV−RV, зміна density.

## Як чіпляється до Setup Engine

Приклад:

- Setup бачить **BTC SHORT біля 89 800**.
- GEX: **верхня стіна 90 000**.
- Система: `89 800 → 90 000` = потенційна **зона реакції**, не «входити бо стіна».

Якщо **одночасно** незалежні шари збігаються:

- liquidation cluster
- BSL
- gamma wall
- HTF resistance
- підхід London/NY
- sweep
- bearish confirmation

→ Setup Engine збирає **один** сетап. Один шар ≠ сигнал.

Після великої експірації вага GEX-рівнів у конфірмації **знижується** (`reliability=post_expiry_low`), поки карта не ущільниться.

## Чого немає в офісі зараз (CONFIRMED код)

Немає полів, снепшотів «до/після 11:00», порівняння серій, IV/RV. LLM не має права вигадувати GEX. Поки немає адаптера даних — модуль або мовчить, або бере **ручний/імпортований знімок** з явною міткою джерела.

## Пріоритет імплементації (після «МОЖНА ВНОСИТИ ЗМІНИ»)

1. Схема state + коротка картка + заборона напрямку.  
2. Стик із Setup: wall/support як named levels поруч із BSL/liq.  
3. Джерело даних (провайдер або ручний JSON-знімок) — окреме рішення, не вигадувати endpoint.
