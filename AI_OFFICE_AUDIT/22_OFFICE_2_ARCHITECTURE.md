# 22. Office 2.0 — архітектура і план (без імплементації)

Код **не змінюється**, поки немає `МОЖНА ВНОСИТИ ЗМІНИ`.

## 1. Що є зараз

Telegram-офіс: LLM-персонажі + REST Binance + таблиця сигналів WATCHING/ACTIVE + рідкий сканер альтів + Mini App-зародок.

## 2. Що працює

- Відповідь на тікер з цифрами ATR/funding.  
- Іноді чесні SKIP на пампі (AKE 400% ATR).  
- Сесійні банери.  
- Збереження зони в БД (ідея правильна).  
- Дарина/circuit як аварійні гальма.

## 3. Що не працює

- Сам сказати «зона / sweep / чекаємо confirm».  
- Короткий сигнал як продукт.  
- BTC як головний watch.  
- REVIEW vs POSITION.  
- Статистика реальних угод.  
- Книги → detector.

## 4. Головна причина

Немає контуру **MARKET → EVENT → ZONE → TRIGGER → CONFIRM → SIGNAL**. Є **CHAT → LLM → TEXT**.

## 5. Дублі

Три скори (probability, edge, gerchik). П’ять LLM на один сетап. Банери + домашка + скан + ручний аналіз на тому ж BTC.

## 6. Прибрати (логічно)

Хор агентів на кожен SKIP. Обов’язкові лекції Марічки в основний чат. Священні 85 без статистики. Proxy як «ліквідації».

## 7. Критично не вистачає

Watchlist рівнів; детектор sweep на 5m/15m; intent flags; короткий SIGNAL; журнал з MFE; BTC в проактивному моніторі (не обов’язково в «сканері 200 альтів»).

## 8. Цільовий пайплайн

```
MARKET DATA (REST+опційно WS)
  → CONTEXT MODULES (price, liq, OI, funding, session, optional GEX/whale)
  → EVENT ENGINE (level touch, sweep, displacement)   # без LLM
  → WATCH ENGINE (підписки користувача і системи)
  → SETUP ENGINE (scalp | intraday | swing окремо)
  → CONFIRMATION (мікро BOS / reject — правила + опційний LLM)
  → STATISTICS (чи цей клас сетапа має expectancy)
  → RISK (size, buffer з ATR, не позиція на /review)
  → ORCHESTRATOR (1 коротка українська картка)
  → TRADE MANAGER лише якщо intent=MY_POSITION
  → RESULT → LEARNING (спочатку логи, потім пороги)
```

LLM **не** думає про ринок кожні 30 с. Його будять події або slash.

## 9. Пріоритети

### P0 — баги поведінки (малий diff, коли дозволять)

- Intent: `/review` не створює WATCHING/журнал позиції; `/position` створює.  
- Не ставити новий WATCHING після явного SKIP, або ставити **без** обіцянки «повідомлю», якщо ATR_DEAD.  
- Дедуп ручного символу: 1 аналіз / N хвилин, якщо не змінилось.  
- Не називати «твоя позиція» без прапора.  
- Вирівняти докстрінґ сканера з sleep **або** зменшити інтервал — окреме рішення.

### P1 — основна функція

- Watchlist: символ + рівень + тип (BSL/SSL/entry) + горизонт.  
- Алерти: APPROACH / TOUCH / SWEEP / CONFIRM (коротко).  
- BTC/ETH завжди в session monitor (Азія теж), сканер альтів — другий контур.  
- Три режими `/scalp` `/intraday` `/swing`.  
- Картка сигналу як у п.45 ТЗ.  
- Один бот-оркестратор (імена можна як підпис).

### P2 — статистика

- Лог кожного SKIP/SIGNAL з ціною t0.  
- MFE/MAE post-hoc.  
- Перегляд порогу 85 **після даних**.  
- Buffer стопа з ATR-дослідження, не з віри.

### P3 — Mini App

Головна: BTC, режим, рівні, активні події, setup.  
Сигнали / статистика / мої позиції / сканер.  
Чат — стрічка подій, не енциклопедія.

### P4 — виконання угод

Лише коли ручний трейдинг стабільний. Зараз **не треба**.

## 10. Що можна без повного переписування

P0 intent + anti-spam WATCHING + BTC watchlist poll на існуючому `monitor_active_signals`.  
Скоротити output Марічки **конфігом max_tokens / окремий топік**, не «список заборонених слів».

## 11. Що краще переписати

Сканер як «найкращий альт раз на годину + 6 LLM».  
Потрійний score.  
Персонажі як окремі повні LLM на кожну подію.

## 12. Що тестувати

- REVIEW не пише `trade_journal` / не ACTIVE.  
- Sweep 5m: фікстура свічок → алерт без користувача.  
- SKIP не створює дубль watch.  
- BTC не в EXCLUDE для **watch**, лише політика для альт-сканера.  
- Повідомлення сигналу < 500 символів, є Entry/SL/TP.

## Slash (пропозиція, не фінал)

Залишити список з ТЗ. Додати `/btc` як status+levels без лекції. `/why` читає **останній event id**, не перераховує книгу.

## Віктор

Окремий `/psych` або топік. Не в хорі 08:00.
