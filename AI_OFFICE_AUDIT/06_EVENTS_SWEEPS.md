# 06. Події та sweep

## Чи є pipeline WATCHING → ZONE → SWEEP → CONFIRM → SIGNAL?

**ABSENT як state machine.**  
Є:

- DB `WATCHING` = збережена entry-зона з тексту LLM;  
- poll ціни;  
- якщо ціна в зоні і **немає SL/TP** → знову `full_auto_analysis` (або cooldown 4h);  
- якщо є SL/TP → `ACTIVE` + «ЦІНА В ЗОНІ — входь!»;  
- **немає** окремого детектора «sweep саме цього рівня» і алерту `🚨 SWEEP`.

## Як код «бачить» sweep

`fetch_liquidity_sweep(symbol, tf="1h")`: останні 3 свічки 1h.

- BSL: high поточної > max(high[-3], high[-2]) і close < цей рівень.  
- SSL: симетрично для low.

Це **грубий патерн 1h**, не підписка на азійський хай 87247. Edge дає **+20**, якщо прапорець true **на момент виклику**.

Якщо виклик о 11:18, а sweep був на 5m о 07:35, **1h close може вже не кваліфікуватись** → Лев пише «немає sweep». Це узгоджується з кейсом 23.09.

2. Не було доведеного рядка WATCHING саме на 87247 з алертом zone-hit (немає в чаті `ЦІНА В ЗОНІ` по BTC того ранку).  
3. Poll поза KZ = **15 хв**, і навіть тоді перевіряється **вхід у збережену зону**, не «азійський хай прокололи».  
4. Sweep-функція не крутиться як окремий event loop по watchlist рівнів.

**CONFIRMED:** прогалина моніторингу.
