Зафіксовані рішення Тетяни:
1. Офіс має стати **радаром подій**, не коментатором на запит.
2. **P0 №1 — два контури:** Office і scanner без спільного стану. Ціль: один MarketState (REGIME, WATCH, EVENT, CONFIRMATION, SIGNAL, BOT ACTION, TRADE).
3. Не KPI «більше сигналів» і не «зменшити % Лева». Агенти = модулі з унікальною роллю.
4. 804 «сигнали» не використовувати; класифікація MENTION→…→RESULT.
5. Debrief (~128) зберегти, з’єднати з RESULT.
6. Назар: при помилці API не писати «новинний фон чистий» (у чаті 22 такі репліки).
7. GEX = характер, не напрямок; коротка картка.
8. Mini App як GGShot **за UX** (Home, Signals, Positions, Stats, Scanner, короткі пуші). Auto-trade / ENTER на біржу = **P4**, після радара.
9. NO TRADE = підсумок моніторингу, не основна діяльність.
10. Писати українською, коротко.

Завдання цього кроку (без коду, якщо немає МОЖНА ВНОСИТИ ЗМІНИ):
- Звірити, що MASTER і файл 24 збігаються з цим списком; дописати лише прогалини з доказами.
- Якщо є команда МОЖНА ВНОСИТИ ЗМІНИ — одна зміна: каркас MarketState **або** intent `/review`≠`/position` **або** Назар fail-closed. Не все одразу.

Не вигадуй Binance/GEX дані. У cloud VM ф’ючерси можуть бути HTTP 451.
