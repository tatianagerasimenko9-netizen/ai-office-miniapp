# 24. Що є / змінити / прибрати / план

Зафіксовано 2026-09-25 з аудиту коду + JSON групи AI Office + уточнень Тетяни (ChatGPT) + референс GGShot.  
**Код не змінюємо**, поки немає `МОЖНА ВНОСИТИ ЗМІНИ`.  
Не ставити ціль «більше сигналів».

## Головний висновок

Лев навчився казати NO TRADE — це плюс (травень «треш/стоп» → вересень «умова не виконана»).  
Проблема: офіс = **аналітичний коментатор**, не **торговий радар**.

Очікування: «слідкуй і скажи, коли щось сталось».  
Факт: «запитай монету — поясню на 1500 слів, а sweep підтверджу після питання».

P0 №1: **дві системи без спільного стану** (Office vs scanner_bot / `file-1`).

## B. Що ПОКРАЩИТИ / ЗМІНИТИ

### 1. Один центральний стан (P0 №1)

Зараз:

```
OFFICE: аналіз → NO TRADE / WATCHING / текст
SCANNER: свої картки → TRADE у своєму каналі
```

Може бути: Лев NO TRADE, сканер LONG, угода відкрита.

Ціль одного рядка на символ:

```
BTCUSDT
REGIME: RANGE
WATCH: BSL 86525–86610
EVENT: BSL SWEEP DETECTED | none
CONFIRMATION: WAITING | YES | NO
SIGNAL: NO | SHORT …
BOT ACTION: BLOCKED | ACCEPT
TRADE: none | AUTHORIZED
```

Після confirm — коротка картка Entry/SL/TP/RR.  
`file-1` не переписувати; протокол: офіс **ACCEPT/BLOCK** → сканер (або майбутній executor) слухає стан. Поки сканер автономний — хоча б **дзеркало статусу** і явний BLOCK у MAIN.

### 2. Радар замість Q&A

Стрічка (один символ, без 17 повідомлень):

- 👀 APPROACH  
- 🚨 SWEEP  
- 🟢 SIGNAL (після confirm)  
- 📈 TP1 / SL→BE  
- або після моніторингу: `NO TRADE. Причина: sweep не підтверджено`

NO TRADE = **результат моніторингу**, не основна робота.

### 3. Класифікація не «804 сигнали»

804 **не підтверджено** (у JSON 472 токен-хіти Лева, ~4 картки). Далі рахувати тільки:

MENTION → SETUP → WATCHING → PRE-ALERT → EVENT → CONFIRMATION → SIGNAL → ENTRY → TP/SL → RESULT → DEBRIEF → STATISTICS

Debrief з’єднувати з SIGNAL→TRADE→RESULT, не лише з рядками, що випадково в БД.

### 4. Intent

`/review` = чужий сигнал, не позиція, не журнал ENTRY.  
`/position` = вести угоду.  
Не писати «твоя позиція» без прапора (кейс 23.09 11:28).

### 5. Події / sweep / ATR

- Named levels, poll 1–5m на watchlist (BTC завжди).  
- Sweep не лише 3×1h на виклик LLM.  
- ATR_DEAD: знімати watch **і сказати**; не крутити ручний `Ake` 11 разів.  
- Сканер альтів ≠ монітор BTC (прибрати BTC з EXCLUDE **для watch**, не обов’язково для альт-конвеєра).

### 6. Назар (дрібниця, але баг)

**22/45** повідомлень: `Новинний фон чистий. Входити можна.`  
При помилці API: `NEWS DATA UNAVAILABLE`, ніколи «фон чистий».

### 7. Контекст-модулі (ролі, не купа індикаторів)

PRICE, LIQUIDITY, LIQ HEATMAP, **GEX (характер, не напрямок)**, OI, FUNDING, WHALES, NEWS, SESSION, STRUCTURE, PATTERNS, STATS → Setup Engine.

### 8. Mini App (P3), не копія GGShot auto-trade (P4)

Див. `25_MINIAPP_GGSHOT.md`. Спочатку Home / Signals / Positions / Stats / Scanner / короткі пуші. Кнопка «вхід на біржі» — **після** радара і єдиного стану.

- Хор 5–6 агентів на один SKIP / ранок.  
- Лекції Марічки в основний чат (перенести в топік або внутрішній модуль).  
- Віктор у шаблоні 08:00.  
- Новий WATCHING після явного SKIP + обіцянка «повідомлю».  
- Метрика «сигнал» = слово LONG у чаті.  
- Поріг 85 як святиня без статистики.  
- Proxy 24h high як «heatmap ліквідацій».  
- LLM-вигадка GEX.  
- Цілі «15 сигналів/день» і «зменшити Лева % чату» як KPI.  
- Змішувати PnL My Crypto Scanner з журналом офісу.  
- Автоторгівлю як перший крок (GGShot ENTER — орієнтир **пізніше**).

## D. Покроковий план (коли дозволять код)

**Крок 0 — зараз (документи):** цей файл + MASTER. Готово.

**Крок 1 — P0 протокол стану (1 зміна за раз)**  
Єдиний об’єкт MarketState на символ. SCANNER_ACTION = BLOCKED якщо OFFICE SIGNAL=NO. Intent review/position. Назар: не «чистий» при fail API. Антиспам WATCHING.

**Крок 2 — P1 радар BTC**  
Watchlist BSL/SSL. Повідомлення APPROACH / SWEEP / CONFIRM / SIGNAL. Без 6 LLM на подію.

**Крок 3 — P2 статистика**  
Ланцюг SIGNAL→ENTRY→RESULT→debrief. Класифікація етапів на історії чату+БД (Render dump). Перегляд 85 і SKIP **після** даних. Історичні свічки — не з цієї VM (451).

**Крок 4 — P3 Mini App**  
Екрани як у MASTER. Чат = notifications.

**Крок 5 — P4 виконання**  
За зразком GGShot: пресет ризику, ENTER одним тапом, ордери на біржі. Тільки коли SIGNAL у спільному стані AUTHORIZED. Тетяна обирає, не «брати всі сигнали».

Кожен крок: один PR, тести, без рефактору всього.
