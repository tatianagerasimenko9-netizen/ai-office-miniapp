# Частина II — Застосування збірника рекомендацій

*(Нижче — аналіз у зв’язці з ролями з `OFFICE_RULES_UA.md` і правилами офісу: як перетворити `OFFICE_AI_RECOMMENDATIONS_UA.md` на користь, а не на хаос. **Це не пункти 38…74 і не «другі 37»** — окремий розділ-інструкція.)*

## 1. Спочатку про правила (рамка)

| Принцип офісу | Що зі збірника підходить | Що суперечить або треба обережно |
|---------------|--------------------------|-----------------------------------|
| Коротко, по суті, українською | «Brain» з ChatGPT: 1–3 рядки, не повторювати, мовчати якщо нічого додати | Довгі ICT-розбори в кожному повідомленні — це контент для **бази знань**, не для кожного сигналу |
| Не вигадувати дані | Grok: Софія лише з **реальної** бази/журналу; ієрархія джерел | Промпти з «7 з 9 у плюсі» без RAG/журналу → **галюцинації**; заборонено до впровадження пошуку |
| Фінал рішення | ChatGPT: Лев дає **ВХІД / ЧЕКАЄМО / ІГНОР** як керівник | У `OFFICE_RULES_UA.md` ще може бути формулювання про фінал від execution і `FINAL DECISION` англійською — **узгодити один раз** у файлі правил (хто фіналить: Лев vs Марко), щоб документ = код |
| Sidecar, ядро не чіпати | Увесь RAG/Chroma/нові фільтри — **тільки** в Office | Приклади коду «встав у scanner_bot» — **ігноруємо** для `file-1.py.py`; логіка в `office_bridge` / окремих сервісах |
| Анти-хаос | Чіткий порядок реплік, один фокус — **сигнал** | «Жарти й емоції» — дозволено легко, але не 20 повідомлень і не замість рішення |

**Висновок:** збірник корисний як **продуктовий і навчальний шар**; у проді застосовувати **поетапно** і через фільтри «коротко / правда / не ламати ядро».

## 2. По ролях — що взяти з користю

**Лев (стратегія)**  
- З ChatGPT: запускає дискусію, ставить питання, збирає думки, фіналізує рішення однією фразою + умова.  
- З Claude: прибрати «корпоратив» — не повторювати гасла, вести як у чаті команди.  
- **Як використати:** оновити сценарії та ланцюжок у bridge: явний «старт від Лева» і «фінал від Лева» — **або** зафіксувати в правилах іншого фіналіста; головне **однаково скрізь**.

**Макс (радар)**  
- Збірник: ліквідність, funding, об’єм, «куди можуть знести стопи» — **без** фінального «заходимо/ні».  
- **Як використати:** у репліках і в `!scenario` — лише контекст ринку; реальні funding/ATR — коли **джерело даних** їх дає; інакше — «недостатньо даних» (як у правилах).

**Назар (новини)**  
- Час до події, сила ризику, без рішення.  
- **Як використати:** бінарність/короткість; не змішувати з довгим ICT-текстом.

**Софія (memory)**  
- RAG, бібліотека `setups/`, `reversals/`, лише реальні кейси.  
- **Зараз без RAG:** заборона імітувати статистику; дозволено узагальнення з `trade_journal` (якщо є в коді) або «база ще не підключена».  
- **Потім:** окремий репо markdown → опційно Chroma; репліки **1–2 речення** з фактом з бази.

**Дарина (ризик)**  
- % ризику, вето, «не ліземо».  
- **Як використати:** узгодити з veto/cooldown у bridge; тон жорсткий, але людський.

**Марко (execution)**  
- План входу, SL, TP, RR **після** рішення; ICT-комбінації.  
- **Як використати:** формулює **план**, не «перемагає» Дарину/Лева; довгі назви сетапів — гілка «Техніка» або база знань.

**Олеся**  
- Моніторинг, PnL, debrief; автозанесення в базу — **процес**, не флуд у «Загальному».  
- **Як використати:** щоденний звіт є; далі — короткі пост-угодні нотатки для майбутньої Софії/RAG.

**Віктор (psych)**  
- Серії збитків, tilt, дисципліна.  
- **Як використати:** сценарії після серії SL або коли learning guard бачить повтор; **1–2 речення**, без моралі на абзац.

**Артем (dev)**  
- Інфра, Chroma, GitHub token, стабільність.  
- **Як використати:** гілка **«Техніка»**: деплой, БД, RAG, помилки API — не змішувати з торговим дискурсом у «Загальному».

## 3. Три шари застосування

**Шар A — Поведінка діалогу (найшвидший ефект)**  
Ідеї з критики офісу + brain: сигнал як центр, порядок реплік, Лев координує, не повторювати, фінал одним рішенням. Реалізація — `office_bridge` (ланцюжок, сценарії), без нових сервісів.

**Шар B — Тон і «живість»**  
Claude + ChatGPT: прості фрази, імена, легка емоція, без «RISK:» і назв звітів у видимому чаті.

**Шар C — Пам’ять і ICT (довгий хвіст)**  
Окрема **людська** бібліотека (markdown), потім RAG. Великі таблиці FVG/CHOCH — **навчальний контент** для репо, не обов’язковий вивід у Telegram на кожен сигнал. Ієрархія джерел: спочатку **твій** журнал і розбори.

## 4. Конфлікти в самому збірнику

- «Усі аналізують funding, ATR, FVG…» vs короткі репліки → кожен **1–2 фактори** у своїй зоні; решта в базі або в `!scenario`.  
- «Все в одному General» vs три гілки → **Загальний** = desk; **Задачник** = таски; **Техніка** = Артем, RAG, системні алерти.  
- MVP-код з ChatGPT — **референс оркестрації**, не копіпаста в торговий бот; ідеї в async relay/bridge.

## 5. Практичний порядок «що робити далі»

1. Узгодити в `OFFICE_RULES_UA.md`: **хто оголошує фінал** (Лев чи Марко) і формулювання українською — документ = код.  
2. **Шар A:** ланцюжок і сценарії «сигнал → черга → фінал».  
3. **Шар B:** шаблони без залишків «звітності» у видимому тексті.  
4. **Шар C:** приватний `AI-Trading-Knowledge-Base` і 10–20 **реальних** кейсів; Софія без RAG не цитує «7 з 9».  
5. Потім RAG (Chroma або простіше) для пошуку — з правилом «немає даних — кажу чесно».

**Наступний технічний крок (за командою «пиши»):** оновлення `OFFICE_RULES_UA.md` під фінал Лева + UA-формулювання **або** перший прохід `office_bridge` під порядок Макс → Назар → Софія → Дарина → Марко → Лев, узгоджений з veto/вердиктом.
