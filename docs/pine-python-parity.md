# Звірка Pine ↔ Python без платного CSV

## Як це влаштовано
- `office_pine_ref.py` — **буквальний порт** повного Pine-коду ICT SMC HUNTER v9.9 (бар за баром, з семантикою Pine: `x[k]`, `var`, RMA/EMA-старт, півоти з підтвердженням, `crossover`, сесії Київ).
- `office_pine_parity.py` / `scripts/compare_pine_python.py` — проганяє еталон і продакшн-детектори (`office_ict_hunter.py`) на **одних і тих самих свічках** і рахує: скільки разів спрацювало в Pine / у Python / разом.
- `scripts/test_pine_ref.py` — тести семантики Pine на вручну зібраних даних.
- На production один раз (подія `LAUNCH_DIAG`, `task=pine_parity`) проганяє це на реальних 15m свічках з архіву Binance для BTC/ETH/SOL/ENA.

## Що знайдено (синтетичні свічки, 4 070 барів; на реальних — у БД після deploy)
| Що | Pine | Python |
|---|---|---|
| Pine-файл у репозиторії | повний код у чаті власниці | `office_worker_library/indicator/ict_smc_hunter_v9_9.pine` — фрагмент на 142 рядки БЕЗ SMS/3D/3T/iFVG/AMD. Патерни в Python писались без першоджерела. |
| 3 Tap | підтримка й опір симетрично, вікно 25 барів, допуск 0,15×ATR | LONG спрацьовує майже на кожному барі (4066 з 4070), SHORT майже недосяжний (4 проти 396): цикл повертає LONG першим |
| Inversion FVG | перетин останнього FVG з допуском 0,25×ATR | спрацьовує у 7–12 разів частіше |
| AMD | перевірка «вузької» 1-ї свічки, ступені HIGH/CONF/MANIP | без перевірки; ~3,5× частіше, збігів ~5% |
| SMS, 3 Drives | розширений рендж, свіп ліквідності, півоти 3/3 | інші умови; збіг 15–40% |
| Turtle Soup | 5 барів | 20 барів |
| Азійський рендж | остання сесія | min/max по ВСІХ барах вікна (різні доби) |
| MO | тримається до наступного 07:00 Київ | до 07:00 Київ = None (фільтр вимикається) |
| EMA55/200, денні EQ 0,786 / OTE 0,5 | — | **збігаються точно (Δ=0)** |

Score: у Pine це 20-бальна сума ~20 компонентів (сесії, обсяг, RSI, рівні, AMD…); у Python — лише сума 7 патернів. Це різні моделі, числа `hunter_score` з Pine-таблицею не порівнювати.

## Що НЕМОЖЛИВО перевірити без TradingView
1. **Чи мій порт = те, що реально малює TV.** Порт перевірено лише за текстом Pine й документацією семантики; 100% гарантії без виходу TV немає.
2. Рівність цін у `ta.pivothigh/low` (яку з однакових точок TV вважає півотом) — на float-даних майже не трапляється.
3. Початок історії EMA/RMA: TV рахує від тих барів, що завантажені на графік, ми — від початку архіву; різниця лише на початку ряду.
4. Обсяг: TV-символ (напр. BINANCE:BTCUSDT.P) і архів Binance можуть мати дрібні відмінності.
5. Поведінка `request.security` на незакритому барі в реальному часі (на історії — збігається).

## Безкоштовна ручна перевірка (без CSV)
У БД лежить `samples_pine` — 12 останніх спрацювань еталона (час Київ, відкриття бару) для кожного символу. Відкрий індикатор на BINANCE:<символ>.P, 15m, глянь ці часи: мітка SMS / 3D / 3T / iFVG / AMD має бути на цьому барі. 2–3 збіги/розбіжності достатньо, щоб підтвердити або спростувати порт.

## Що далі (не зроблено, бо змінює рішення Лева)
Переписати детектори в `office_ict_hunter.py` за еталоном. Це змінить, коли спрацьовують патерни, а отже й score, тож робиться після твого рішення.

## Рішення власниці (2026-10-01): тимчасове вимкнення
- ICT SMC HUNTER і PUMP & DUMP HUNTER **не додають бали й не підтверджують/блокують** готовий сигнал Лева (`office_indicator_gate.py`).
  Раніше «суперечність» одного з них переводила сигнал у WAIT; тепер вони позначені NOT_CONNECTED/disabled і не обчислюються.
  Також вимкнено: `hunter_score` у картці радара та супровід CONT/ADD для PUMP/DUMP-угод.
- Лишається без змін: структура D1/H4/H1/M15/M5, рівні, SMC/Вайкоф, BOS/CHoCH, OB/FVG, sweep, обсяги, ATR/RSI, ліквідації, OI/funding, сесії, новини, RR, **регресійний канал** (після виправлення математики).
- Код портів, parity-звірка й тести лишаються для доведення. Повернути вплив: `OFFICE_PINE_INFLUENCE=1` (або прибрати ключ із `PINE_PORTS`).
- Виправлено (за рішенням власниці): `_asia_range` у `office_ict_hunter.py` (його бере `office_targets.py` для цілей TP2/TP3) тепер дає рендж ОСТАННЬОЇ азійської сесії, як у Pine, а не min/max по всіх добах вікна. Тест порівнює з еталоном на кожному барі.
