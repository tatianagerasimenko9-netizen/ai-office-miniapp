# Shadow-план (нічого не міняє live; лише додаткові поля/окрема таблиця)
Сигнал B&R іде як зараз; на нього додатково записуються прапорці «пройшов би фільтр X». Порівняння на нових даних.

| Прапорець | Опис | Статус параметра |
|---|---|---|
| f_min_stop | стоп ≥ X% від входу | X — ГІПОТЕЗА (14.10: 0.5% дав −0.245R проти −0.467R) |
| f_hour | година/сесія UTC у «кращій» множині | множина — лише після holdout |
| f_pause_sl | немає SL по цій монеті/напряму за останні N годин | N — ГІПОТЕЗА |
| f_dedup | перший сигнал на монету/напрям у вікні | вікно — ГІПОТЕЗА |
| f_htf_align | напрям збігається з трендом H1/H4 | визначення з `office_br` HTF map |
| f_ltf_confirm | підтвердження M5/M1 (вже логується `[br-htf-shadow]`) | — |
| sl_htf_price | стоп за найближчим H1/H4/D1 swing + буфер | ТФ/буфер — ГІПОТЕЗА, сітка |

Критерій успіху (заздалегідь): net R з фільтром > без, CI кластерного bootstrap різниці не містить 0, ефективне n не менше узгодженого у звіті ChatGPT; до того — НЕ ПІДТВЕРДЖЕНО.
