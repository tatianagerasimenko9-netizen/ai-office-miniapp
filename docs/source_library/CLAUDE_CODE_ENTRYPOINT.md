# Claude Code — точка входу до оригіналів методик

**ЗАПУСТИ ЦЕ ЗАВДАННЯ З РЕПОЗИТОРІЮ**, не покладайся на перекази в повідомленнях.

## Крок 0. Перевір наявність джерел
1. `docs/source_library/README.md` і `PROVENANCE_AND_EVIDENCE_RULES.md` прочитай одразу.
2. Перевір, чи реально існують `source_library/raw/2026-10-11/` та `source_library/manifests/2026-10-11/INDEX.csv`, чи збігаються хеші й кількість файлів.
3. Якщо відсутні, **зупини лише імпорт/аналіз невидимих джерел** і чесно повідом `ORIGINALS_NOT_AVAILABLE_IN_REPOSITORY`. Не генеруй «аналіз 415 скриншотів» із їхнього списку. Підкажи власниці, як передати оригінали в приватне сховище/робочу папку Claude, зважаючи на авторські права.
4. Якщо джерела доступні, розпакуй/індексуй без зміни файлів, запиши hash, файл, атрибуцію і первинний порядок.

## Крок 1. Розділи авторство, застосування і докази
- `DARIA_METHOD_SOURCE`: сьогоднішня навчальна добірка Дарії за походженням; зміст кожного правила лише з оригіналів.
- `GERCHIK_SOURCE`, `SMC_ICT_SOURCE`, інші перевірені книги/методики — окремо.
- `EXTERNAL_OFFICE_REFERENCE`: BTW SHORT та інші сторонні Telegram-сигнали, лише UX/супровід.
- `OFFICE_PRODUCT_QA`: RUNE та власні картки.
- `NEEDS_SOURCE_MAPPING`: невстановлені матеріали.

Зроби machine-readable registry `docs/source_library/rules_registry.jsonl` після фактичного читання оригіналів. Для кожного правила вкажи джерело аж до сторінки/кадру.

## Крок 2. Реальна інтеграція в існуючий AI Office
- Не будуй другу незалежну торгову систему.
- Верифіковані джерела перетворюй у формалізовані ознаки, з тестами, що доводять відповідність прикладам автора.
- Старший ТФ -> сильна старша свічка/структура -> старший Fibonacci за завершеним імпульсом -> відкат до старшої зони -> підтвердження на молодшому ТФ. Це лише один сценарій; інші не змушуй виконувати всі умови одночасно.
- Окремі сценарії: рівень Герчика, break/retest, sweep/BOS, Wyckoff, Elliott та патерни — **тільки якщо реально є джерело**.
- У Telegram та Mini App причини однакові, конкретні й із доказами; не прикрашай вигаданими підтвердженнями.
- Replay без підглядання в майбутнє, витрати, порівняння з наявним алгоритмом, paper-forward; production LIVE gates не чіпати.
- Telegram наслідує зрозумілу подачу і життєвий цикл з прикладів, **не механічно копіює чужі торгові рівні/відсотки**.

## Крок 3. Приймання
У звіті окремо:
1. Кількість оригіналів, реально прочитаних із байтів, і хеші.
2. Кількість правил із доказовим посиланням на конкретний скриншот/сторінку.
3. Кількість підтверджених реалізацій, їхні тести та replay/shadow результати.
4. Реальні Web/Worker SHA, фактичний стан Telegram → Mini App → paper → postmortem.
5. Що лишилось `UNVERIFIED` / `WAITING_FOR_MARKET` / `ORIGINALS_NOT_AVAILABLE_IN_REPOSITORY`.

**Не звітуй «готово», якщо додано лише docs.** Дії з платним доступом, перевантаженням GitHub авторськими книгами, фінансовою LIVE-торгівлею чи ризиковою міграцією вимагають окремого погодження.
