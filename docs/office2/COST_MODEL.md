# Модель витрат paper-угод (11.10.2026)

Єдина константа: `office2/learning/costs.py` → **0,15 % кола від ноціоналу** = комісії 0,10 % (taker 0,05 % × 2 сторони) + slippage/spread 0,05 %.

| Складова | Значення | Джерело | Статус |
|---|---|---|---|
| Taker-комісія | 0,05 % за сторону | публічна сітка Binance USDT-M, рівень VIP0 | **припущення**: у цьому середовищі немає доступу до Binance, фактичний рівень рахунку власниці та знижка BNB невідомі |
| Maker-комісія | 0,02 % за сторону | та сама сітка | не використовується в основній моделі; є в чутливості |
| Spread | входить у 0,05 % | — | припущення (для ліквідних USDT-M зазвичай 0,5–3 bps, але на цій парі не виміряно) |
| Slippage | входить у 0,05 % | припущення Office2 | не виміряно на реальних виконаннях (реальних ордерів немає) |
| Funding | **не враховано** | — | не моделюється; тримання через 00/08/16 UTC додає ± ставка × ноціонал |

## Чому збиток −$11,99 при ризику $10
Ризик $10 = відстань до SL × розмір. Витрати рахуються від ноціоналу, не від ризику: LINK LONG (стоп 0,76 % від входу) → 0,15 % / 0,76 % = **0,20 R** додатково (≈ $1,99). Тому збиток на SL = −1,20 R. Чим вужчий стоп, тим більша частка витрат (COST_HEAVY ≥ 0,25 R — вже позначається в `learning_flags`). Це не помилка обліку, а властивість малих стопів.

## Чутливість (на $1330 ноціоналу, LINK)
- модель Office2 (taker вхід + taker SL + slippage): ≈ $2,0;
- taker вхід + maker TP + половина slippage: ≈ $1,3 (лише для виходів по TP, SL завжди taker/stop-market).

## Що потрібно, щоб зняти припущення
1. Фактичний тариф рахунку власниці (VIP-рівень, BNB-знижка) — тільки власниця.
2. Вимірювання spread/slippage на реальному виконанні — можливе лише після окремо погоджених реальних ордерів (зараз заборонені).
3. Funding: історичні ставки з публічного API (`/fapi/v1/fundingRate`) у prod; додавання в PnL — окремим PR після перевірки.
