# Office2 Brain v2 (`o2-brain-2.0`) — інтегрований конвеєр і gap-аудит

LIVE BETA, UNPROVEN. Office нічого не торгує сам. Версія Brain заморожена: `version_id` є в кожному сценарії (`office2_live_scenario.version`, `office2_live_signal.version`, snapshot `version_id`). Відкат: `OFFICE2_BRAIN=1` (brain v1).

## Конвеєр рішення (`office2/brain2.py` + `office2/evidence.py`)
HTF → BTC/ETH/ринок → сильні рівні/mirror/люфт → PDH/PDL/PWH/PWL/PMH/PML/сесії → sweep-подія або захист origin-зони → MSS/BOS з displacement → нога → зона входу (OTE 62–79% ∪ OB/FVG) → контрольований ретрейс у зону → M15-тригер → структурна інвалідація → люфт (медіана проколів саме цього рівня) → SL → перевірка шуму ATR(M15) (стоп не розширюється) → цілі від реальних рівнів → простір ≥ 1R → розмір за фіксованими $ → портфельна ємність → READY / WAIT / NO_TRADE / MISSED / INVALIDATED.

`sweep → reclaim → 1 бар` більше НЕ дає READY: sweep — лише подія, READY потребує повної послідовності (тест `test_no_ready_from_sweep_reclaim_hold_only`).

## v2.1 (o2-brain-2.1): цілісна теза до рішення
Розбір першого production READY (ETH LONG 07.10 11:30 Київ) показав: рішення приймав ланцюжок sweep сесійного рівня → зсув → OTE → M15, а карта TF і докази рахувались ПІСЛЯ READY. Виправлено:
- **Рівні:** PDH/PDL/PWH/PWL — лише попередня завершена доба/тиждень (давніші = D1H/D1L/W1H/W1L); кожен рівень має `taken_ts` (знято чи живий пул); цілі, перешкоди й карта ліквідності беруть лише живі рівні; перешкоди ближче 0,25 R більше не відкидаються.
- **Карта TF зверху вниз:** MN → W1 → 4D → 3D → D1 → H4 → H1 → M15: актуальний стан `trend_eff` (ціна за останнім swing = структура зламана), dealing range, premium/discount лише всередині діапазону, свінги, відстань до живих пулів у $, %, ATR, R. 4D/3D — ресемпл D1.
- **Докази ДО рішення:** `brain2.assess` читає карту, докази модулів і ринок BTC для кандидата READY. Докази самі не блокують. Умовний gate один: КОНТРТРЕНД (H4 проти, або D1 проти за H4 не за напрямом) + локальна подія (не HTF) + немає доказу повернення (H1 уже в напрямі / CHoCH H1) → WAIT 3/3 з числовою умовою; HTF-локація або доказ → READY. У знімку: `integral` (ЗА/ПРОТИ, що вплинуло на рішення, що ні) і `map`.
- **Реплей на момент часу без lookahead:** `office2/replay_at.py`, змінна `OFFICE2_REPLAY_AT="SYMBOL@epoch,…"` (діагностика, нічого не відправляє) → таблиця `office2_replay_result`.
- Premium/discount поза діапазоном більше не називається «ЗА» (було «−209 %»).

## Один продукт: Brain v2.1 всередині основного Mini App
Окремого «Office2» інтерфейсу більше немає. `/office2` перенаправляє в основний Mini App (`/v2`), де Brain v2.1 — механізм рішень, а екрани ті самі (Офіс, Радар, Сценарії, Журнал, Ризик).
- **Картка сценарію** (`/v2?scenario=O2|…`, кнопка «Сценарій» у Telegram) — та сама сторінка з графіком, зонами, SL/TP, кнопкою «Я відкрила угоду» і журналом подій. Нові блоки: чому тут і зараз (ЗА/ПРОТИ, що вплинуло на рішення), послідовність до READY, карта MN→M15, докази, ринок на момент сигналу → зараз → що змінилось, хід сценарію. Рівні заморожені на момент сигналу.
- **Єдиний Radar** (`/api/v2/radar`): READY → ARMED 3/3 → WAIT 2/3 → WAIT 1/3 → інші → NO_TRADE → MISSED → INVALIDATED. Для кожного: монета, напрям, ціна зараз, потрібний рівень (`need` з тези Brain), відстань, скасування, термін дії. Shortlist сканера й спостереження Лева — на тому ж екрані нижче, окремої логіки статусів немає.
- **Списки й журнал:** надіслані READY Brain показуються разом зі сценаріями Лева (`kind=brain_v2`, `brain=v2.1`); статистика Brain у Журналі → «Модельна статистика» окремо за версією Brain (v1 / v2.1).
- **Сценарій ≠ угода:** SL/TP сценарію — стан моделі (`HIT_SL`/`HIT_TP3`); особиста угода починається лише з «Я відкрила угоду» (існуючий потік `trades`, не змінено).
- Telegram не змінено: коротка картка + кнопка → `/v2?scenario=…`.
- Відкат інтерфейсу: ці зміни лише читають існуючі таблиці `office2_*`; нових таблиць і міграцій немає. `OFFICE2_BRAIN=1` / `OFFICE2_LIVE_DELIVERY=0` лишаються перемикачами Brain/доставки.

## Release hardening (після розбору LTC SHORT 07.10)
Виправлено лише обчислення/відображення, торгові пороги не змінювались; історичні знімки не переписуються.
- **Ретрейс у зону:** текст кроку тепер залежить від напрямку — LONG: `low … торкнувся зони`, SHORT: `high … торкнувся зони` (у дзеркальних координатах «low» був мінус-high, тому SHORT показував максимум свічки як «low»). Якщо екстремум свічки за дальньою межею зони — «свічка пройшла зону наскрізь, закриття … не за межею». Логіка входу не змінена: дотик = екстремум свічки досяг зони, закриття не за дальньою межею.
- **SL:** знак буфера за напрямком: LONG `екстремум − люфт`, SHORT `екстремум + люфт`. Було `67,91 − 0,03 = 67,94` (SHORT), правильно `67,91 + 0,03 = 67,94` — помилка була лише в тексті.
- **Swing HTF лише по закритих барах:** поточний бар, що формується, не підтверджує swing (раніше міг). У карті `swing_stale` = ціна вже поза останніми підтвердженими swing (описують старіший діапазон; на картці позначається). M5/M1 — «не перевірено» (структура M5/M1 не рахується).
- **«Вплинуло на рішення»** = змінило результат. Умовні перевірки (старша структура, локація, доказ H1) мають `evaluated=true`; `did_affect_decision=true` лише коли вони зробили BLOCK. При ALLOW рішення визначає послідовність подія → зсув → зона → тригер → SL/цілі.
- **Життєвий цикл:** WATCH → WAIT 1/3 → 2/3 → ARMED 3/3 → READY → ENTRY → TP1 → TP2 → TP3 | SL | EXPIRED | INVALIDATED. TP1/TP2 — проміжні (сценарій триває до TP3 або SL); кінцеві: TP3, SL (у т.ч. `TP1→SL`, `TP2→SL`), EXPIRED (входу не було), INVALIDATED/MISSED до READY. Після кінцевого стану головний статус — «TP3 · ЗАВЕРШЕНО» / «СТОП · ЗАВЕРШЕНО» / «СТРОК ВИЙШОВ», READY лишається історичною подією, «Діє до» не показується, ціна зараз підписана як така, що вже не належить результату. Віхи ідемпотентні (ключ scenario_id + час + рівень).
- **Результат — модельний, не PnL:** правила виходу в системі немає, тому реалізованого PnL і суми R не рахуємо. Показуємо факти: що першим (TP чи SL), найдальша досягнута ціль і її R за початковим ризиком (потенціал при утриманні). Особиста угода — окремо, після «Я відкрила угоду».
- **Статистика:** унікальні сценарії за батьківським id (не повідомлення, не цикли), окремо за версією Brain: READY, надіслано, вхід, першим TP / першим SL, TP3, строк вийшов, не завершені, медіана макс. R (потенціал).
- **Затримка життя сценарію:** активні плани Office2 старші 6 год перевіряються по 5m кожні 120 с (було 600 с). Заміри 07–08.10: 1m-шлях 0,5–5 хв, 5m-шлях 3–11 хв від початку свічки дотику.
- **Процедура регресії на історичних моментах:** `OFFICE2_REPLAY_AT="SYMBOL@epoch,…"` на worker → `office2_replay_result` (обидва напрями, без lookahead) → зняти змінну.
