# Робота над помилками на всій історії Brain (feature-study)

Джерело: GitHub Actions run 38133925197 (11.10.2026, `feature-study.yml`), replay Brain v2.1 на свічках Binance-архіву: 29 монет × 3 вікна по 14 днів
(кінці вікон 11.09, 25.09, 09.10) → **N = 1936 рішень READY (без обмежень гейта)**. Результат — модель A (усе на TP1), витрати 0.15 % кола (припущення), SL першим у спірній свічці.
Ознаки — лише з даних ДО рішення (`office2/learning/features.py`). Перевірка: перші 60 % за часом = train, останні 40 % = test; клітинка «STABLE» лише якщо однаковий знак у обох
половинах, |середнє| ≥ 0.10 R і CI з поправкою Бонферроні не містить 0 (n ≥ 60). Тест на шумі (випадкові дані → нічого не знаходить) у `scripts/test_feature_study.py`.

## Головне
* **Загальний результат replay від'ємний: −0.115 R на рішення** (train −0.100 R, test −0.140 R). Brain у цьому replay НЕ має позитивного очікування після витрат. Це replay без гейта і без портфельних обмежень, не LIVE-результат.
* Жодна ознака не робить вибірку прибутковою. Єдина «хороша» клітинка — сесія ASIA (+0.037 R, n=567), але CI включає 0 і train/test близькі до нуля → **не підтверджено**.
* Стійко **гірші за решту** (обидві половини, CI без 0, різниця до решти ≥ 0.10 R):

| Ознака | n | середнє R | решта | train → test |
|---|---|---|---|---|
| вихідні (сб–нд UTC) | 622 | −0.323 | −0.018 | −0.365 → −0.267 |
| витрати ≥ 0.25 R (малий стоп) | 144 | −0.478 | −0.087 | −0.576 → −0.380 |
| сесія OFF_HOURS | 198 | −0.286 | −0.097 | −0.313 → −0.244 |
| відносна сила до BTC 1h = FLAT | 347 | −0.219 | −0.094 | −0.166 → −0.311 |

  Також стійко від'ємні, але різниця до решти < 0.10 R (не беремо в позначки): сесія LONDON (−0.184), FRESH_RAID (−0.175), SHORT (−0.151), counter_trend (−0.169), SESSION-рівні (−0.166), HTF WITH_TREND (−0.154), retest_not_fresh=False (−0.170), Bulkowski «за» (−0.137), btc_1h FLAT (−0.152).
* Перевірка «фільтр з train → test»: фільтр, побудований лише на train, залишає на test 63 з 775 рішень (+0.079 R, +5.0 R) і відсікає 712 (−0.159 R, −113.6 R). Тобто «ефект» фільтра майже повністю — це відмова від майже всього потоку; 63 рішень недостатньо для висновку (n < 30 стабільних незалежних ідей на клітинку). **Правило, що покращує тест надійно, не знайдено.**

## Що впроваджено (без зміни LIVE)
`office2/learning/learned_flags.py` (lf-1): shadow-позначки **WEEKEND, COST_HEAVY, OFF_HOURS** на кожній paper-позиції (LIVE, CONTROL, BACKFILL). Позначка нічого не блокує. Mini App показує ⚑ біля угоди та таблицю «ефект позначки»:
скільки SL було б уникнуто, скільки прибуткових входів втрачено, чистий результат без позначених угод; вердикт INSUFFICIENT доки позначених розв'язаних < 30.
RS_FLAT вимагає відносної сили на момент READY, якої немає у знімку paper-позиції, — не додано.
Автоматична зміна LIVE-фільтрів не дозволена власницею; вмикання як фільтр — лише її окремим рішенням після незалежного підтвердження на нових paper-результатах.

## Обмеження
Replay — не production: інший потік рішень (без гейта 3 SL і портфельного відбору), без реальної затримки доставки, фандинг не моделюється, комісії — припущення. Вікна по 14 днів — три фрагменти, не вся історія.
