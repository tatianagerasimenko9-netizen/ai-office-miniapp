# OFFICE2 · LIVE BETA

**Що це:** decision-support для ручної торгівлі, не доведена стратегія. Статус доказовості мозку — `UNPROVEN` (N2/FLOW-1/v0 не показали OOS-переваги; MOVR-послідовність взята як модель читання історії руху, а не як перевірений edge). Авто-торгівлі немає.

## Ланцюг рішення (office2/brain.py, engine.py)
HTF (W1/D1/H4/H1/M15) → BTC/ETH/breadth/волатильність/relative strength → рівні й ліквідність (PDH/PDL/PWH/PWL/PMH/PML, H4/D1/H1/M15 swing, сесійні H/L, EQH/EQL) → POI → поведінка ціни → локальна структура (BOS/CHoCH лише за наявного тренду) → тригер → структурна інвалідація → SL → цілі → ризик → READY / WAIT / NO TRADE.

Стани: WATCH → WAIT → READY; завершення без READY: NO_TRADE (чогось критичного бракує), MISSED (пізно), INVALIDATED (теза зламана), EXPIRED (час). Кожен перехід у `office2_live_transition`.

* **Теза A (MOVR-тип, SHORT дзеркально):** імпульс ≥3 ATR(H1) → відкат до origin-зони → атаки в зону → стиснення → злам локального lower-high на M15 свічкою displacement (тіло ≥1,2 ATR, закриття у верхніх 35%) → утримання ≥1 закритого бару. Не вимагає однакового напряму H4 і LTF: HTF-тренд пишеться як контекст.
* **Теза B:** sweep ключового рівня + повернення за рівень + утримання.
* **Структурний SL:** дно відкату (найглибша атака в зону) / екстремум sweep − доказовий буфер (медіана глибини проколів M15 цієї монети; запасний 0,2·ATR). Порядок: теза → інвалідація → буфер → SL → розмір. SL не підганяється під RR.
* **Цілі:** найближчі реальні перешкоди за напрямом (рівні/свінги), TP1 ≥ 1 R (як у старому гейті); ближчі перешкоди пишуться в знімок (`obstacles_before_tp1`). Немає цілі — NO TRADE.
* **No-chase:** вхід не далі 0,6 R від рівня пробою/reclaim, пробій не старший за 2 год, інакше MISSED.
* **Ризик:** фіксовані 10 $ на сценарій; Risk Manager: сукупний відкритий ризик ≤40 $, кластер ALT ≤30 $, ≤3 однонапрямлених альти, одна монета — один живий сигнал, одна ідея/рівень, 3 стопи/добу UTC, ≤8 READY/добу.

## Прапорці і відкат
| Змінна (worker) | Дія |
|---|---|
| `OFFICE2_SHADOW=1` | збір станів/кандидатів/наслідків (shadow, вже працює) |
| `OFFICE2_LIVE=1` | рушій WATCH/WAIT/READY пише сценарії й outbox у БД |
| `OFFICE2_LIVE_DELIVERY=1` | доставка READY у Telegram + запис плану в lifecycle (ENTRY/TP1–3/SL/EXPIRED ведуться наявним `monitor_scenario_milestones`) |
| `OFFICE_OLD_READY_DELIVERY=0` | старий Лев НЕ доставляє нові READY користувачу; його план пишеться внутрішньо (rejected, hypothetical-трекінг) для порівняння OLD vs OFFICE2 |

**Відкат (без втрати історії):** `OFFICE_OLD_READY_DELIVERY=1` (старий READY повертається), `OFFICE2_LIVE_DELIVERY=0` (Office2 мовчить), за потреби `OFFICE2_LIVE=0` / `OFFICE2_SHADOW=0`. Усі таблиці `office2_*` адитивні, старі таблиці не змінювались. Активні сценарії старого Лева доводяться до завершення наявним lifecycle.

## Модулі мозку
* Активні: див. `office2/brain.py → MODULES["active"]`.
* Лише контекст: FVG/OB (опис), RSI, taker-дельта останнього бару, режим волатильності.
* Недоступні сьогодні (слот є, у трасі Office2 не підключено): M5/M1 тригери (цикл раз на M15), 4D, OI/funding/L:S/ліквідації, GEX/options, DOM, Bulkowski/Wyckoff/regression channel/Fibonacci-OTE у трасі Office2 (є у production-знімку старого Лева), макро-календар.
* FAILED OOS (Narrative v1, N2, FLOW-1) не мають права самостійно створювати READY. Теза A використовує послідовність MOVR за прямим рішенням власниці як LIVE BETA; результати накопичуються для пакетного аналізу.

## Mini App
`/office2` (і `GET /api/v2/office2`): для кожного READY — РИНОК НА МОМЕНТ СИГНАЛУ (заморожено) / РИНОК ЗАРАЗ / ЩО ЗМІНИЛОСЯ + decision trace; таблиця сценаріїв WATCH/WAIT/NO TRADE/MISSED.
