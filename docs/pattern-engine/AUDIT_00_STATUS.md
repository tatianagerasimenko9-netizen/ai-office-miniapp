# PATTERN ENGINE 2.0 — статус аудиту (початок)

## Блокер: джерела правил немає
- У репозиторії є лише конспект `office_worker_library/books/bulkowski_encyclopedia_chart_patterns/KONSPEKT_UA.md` (опис словами, без формальних identification/confirmation rules).
- thepatternsite.com із цього середовища заблокований мережею (EGRESS_BLOCKED). EPUB 2-го видання є у власниці, але не в репозиторії.
- Тому специфікації патернів «з пам'яті» НЕ пишемо. Потрібне одне з двох: (а) дозволити домен `thepatternsite.com` у налаштуваннях середовища, (б) дати текст/PDF розділів.

## Схема специфікації (кожен патерн = один JSON/YAML, поля з source та версією)
pattern_name, family, direction, required_prior_trend, required_swings, minimum_touches, geometry_rules, allowed_tolerance, duration_bars, volume_rule, confirmation_level, confirmation_rule, invalidation_rule, breakout_rule, target_calculation, throwback_pullback_rule, busted_rule, source, method, version.
Статуси: FORMING → CANDIDATE → CONFIRMED | REJECTED | FAILED/BUSTED. READY не називає патерн, якщо він не CONFIRMED.
Порядок детектора: фактичні свінги/дотики → геометрія → перевірка обов'язкових критеріїв → лише потім назва.

## Попередні знахідки в коді (не залежать від джерела: внутрішні логічні дефекти)
1. `office_bulkowski.flags`: умова «паралельні межі» (`parallel`) перевіряє лише, що обидва нахили ≤ 0,02·ATR/свічку. Проходять і лінії, що розходяться (верх −0,5, низ −2,0 → «прапор»), тобто це не прапор, а розширення. Перевірено на числах.
2. `flags`: лінії межі — МНК по ВСІХ highs/lows корекції (`_fit`), а не по фактичних свінгах/дотиках; мінімальної кількості дотиків і перевірки, що свічки лишаються в коридорі, немає.
3. `flags`: пробій = закриття за усередненою МНК-лінією (а не за найвищим максимумом корекції), тобто підтвердження слабше за «закриття за межею фігури».
4. `flags`: вираз `converge` має зайвий `or`, що робить його незалежним від напрямку (поведінка не змінюється, але код вводить в оману).
5. Трикутники/клини/прямокутник беруть останні ≤5 свінгів (K=2) і підганяють лінії МНК; достатньо 2 свінги на лінію, довжина ≥ 8 свічок. Чи цього досить за джерелом — невідомо до отримання правил.
6. Подвійні/потрійні вершини (`office_patterns`): допуск «max(0,3%; 0,5·ATR)», ≥3 свічки між екстремумами, підтвердження закриттям за шиєю. Варіантів Adam/Eve немає. READY сьогодні може називати «double_top», коли лінія шиї ще не пробита? — перевірити: тег потрапляє лише при `confirmed`.
7. `confirmed_for` повертає лише `kind/level/target/why`; до #119 геометрія не віддавалась і не зберігалась у знімку READY.
8. Свічки підтвердження: для H1-сетапу беруться M15 (40 барів), а для детекції фігур `lookback=80`; для картки — 96 барів M15. Різні вікна дають різні фігури, тому геометрія на картці перевіряється повторним детектором (`evidence_missing`).

## Наступні кроки (після отримання джерела)
1. Каталог усіх патернів → spec-файли.
2. Таблиця: правило джерела | наша реалізація | збігається | що порушено | ризик false positive.
3. Backtest pattern × TF (M5/M15/H1/H4/D1): N, confirmed, failure rate, TP-before-SL, MFE, MAE, breakout follow-through; train/test без lookahead.
4. Допуск до READY лише для тих pattern×TF, що пройшли.
Production-детектор до завершення аудиту НЕ змінюється.
