# Аналіз правила RR (до зміни; правило на production НЕ змінено)

Рішення власниці на розгляді: замість «RR до TP1 ≥ 1,5» — (1) зважений RR ≥ 1,5 за планом 40% TP1 + 30% TP2 + 30% runner (runner = вихід на TP2), комісія 0,10%; (2) RR до TP1 ≥ 1,0. Спершу — цифри «до зміни»: `office_rr_analysis.py` (одноразово на worker: `OFFICE_RR_ANALYSIS_ON_START=1`, лог `[rr]`, лише читання).

Формули й симуляція — у docstring модуля. Унікальні плани з `office_signals` (службові дублі `lev-watch-*` щоциклу зведено за ключем), TP2 із БД або відновлений логікою production зі свічок ДО плану; результат у R за плану виходу на реальних свічках з архіву data.binance.vision; окремо — угоди власниці з `trade_journal` (фактичний R). Тест: `scripts/test_rr_analysis.py`.
