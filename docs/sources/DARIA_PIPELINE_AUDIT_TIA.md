### Чому e008197edf29 отримала «вхід»
1. Це **не реальна й не READY-угода**: Brain на 14:30 перевів сценарій у `NO_TRADE` (ліміт стопів). Карта BLOCKED — навчальна («що було б»); LIVE-гейт спрацював правильно.
2. За `reasons_json`: зсув структури (закриття вище 0,5813), торкання зони (**мінімум 0,5805 = верхня межа зони**) і тригер (**закриття 0,591 ≥ середини зони 0,5785**) — усе в межах одного M15-циклу створення картки. Тобто «відкату в зону» як окремої фази після сильної свічки до тригера не було; тригер = закриття самої сильної свічки (за текстом причин; точний бар перевіряється replay).
3. `plan_of()` (`radar_watch.py`): ціна підтвердження 0,591 була поза зоною → вхід переставлено лімітом на межу зони 0,5805 (`entry_note`).
4. `office_signal_track.simulate`: paper-вхід заповнюється, **коли ціна торкається рівня входу** (`lo ≤ entry ≤ hi`), без вимоги нового тригера/реакції. 14:45 ціна торкнулась 0,5805 → «вхід». Це не підтвердження відкату.
5. У картці був аргумент «проти»: зона в premium діапазону H4 (72%) для LONG. Він не блокує.
6. Стоп 0,568 уже за екстремумом події 0,5722, тож питання не в ширині стопа; MFE 0,95R до стопа показує, що ідея частково працювала, але вхід лімітом по числу сітки без реакції — саме те, що слайд Дарії (кадр 267) називає помилкою.
7. Картка діяла до 18:30 UTC (21:30 Kyiv); паперова позиція, відкрита 14:45, закрилась по SL о 21:00 UTC (00:00 Kyiv) — **після** строку дії картки; відскок після півночі не відноситься до цієї угоди.

### Чому `stops_json`/`stop_eval` = NULL (пункт 7)
Сценарії c4f5 та e008 створені до того, як Brain почав писати блок `stops` у `thesis_json` (в БД: `thesis_json` без `stops` і без `preview.stops`). `backfill_stops()` пропускає такі картки (`continue` без запису), тож NULL — не втрата даних, а їх відсутність на момент рішення. Підміна пізнішими значеннями не робилась і не робиться. У d37a… блок є (три варіанти: 0,567 / 0,56909 / 0,56858).
