# Послідовність Дарії «старший ТФ → проміжні → M5/M1 → вхід» і як вона реалізована (12.10.2026)

Правило джерел: `docs/strategies/SOURCE_RULES.md`. Тут розділено **(1) що підтверджено доступними матеріалами**, **(2) вимога власниці** (USER_REQUIREMENT, 12.10), **(3) наша реалізація** (OUR_IMPLEMENTATION / ГІПОТЕЗА). Числових порогів Дарії не вигадано.

## 1. Що доступно в репозиторії і чого немає
- Є: вторинний конспект docx (`docs/office2/DARIA_ZHDANOVA_METHOD.md`, розділ «APE SHORT»), список прикладів зі скриншотів (SHORT: … C98, GALA, ZRX …; рядок 14 того ж файла), маніфест 415 зображень, `evidence.jsonl` (82 правила).
- Немає (у пісочниці/репозиторії): оригінальні відео, кадри, сам файл `Metodyka_Darii_AI_Office.docx`. За правилом власниці оригінали й фото в публічний репозиторій без дозволу не переносяться.
- Наслідок: **покадрову послідовність ТФ для C98, GALA, ZRX відновити з наявного неможливо** — у конспекті є лише назви монет і напрям SHORT. Для APE SHORT є послідовність подій, але без таймфреймів і рівнів.

| Приклад | Що підтверджено матеріалами | Що НЕ ПІДТВЕРДЖЕНО | Чого бракує | Чи можна будувати решту незалежно |
|---|---|---|---|---|

## 4. Не реалізовано (чесно)
- Спостереження входу між закриттями M15 (`watch`-цикл) — наступний етап; зараз M5/M1 перевіряється на барі M15.
- APE-подібний детектор «ущільнення → слабкі відскоки → пробій + прискорення» (COMPRESSION_BREAK) — лише специфікація; без кадрів ТФ і умов не будується як правило.
- Заміна `STRUCT_BREAK_V0` на умови Дарії — після отримання тексту docx або ключових кадрів у чаті.
