# Правило мінімальної цілі TP1 (1,2% для BTC/ETH/золота, 3% для решти) — аналіз, без зміни порогів

## Що є в коді (факти)
- `office_desk_card.py`: `MAJORS_TP1_PCT = 1.2`, `ALTS_TP1_PCT = 3.0`; `min_tp1_pct(symbol)` залежить **лише від монети**. Тип угоди (`style_ua`: скальп/інтрадей/свінг) на поріг **не впливає**. Тобто окремих правил для скальпу в коді немає, хоча вимоги власниці їх передбачають.
- Правило діє при відправленні картки (`prepare_desk_send`), у Execution Planner Mini App і в моєму відстеженні умов (`office_lev_watch`, ті самі перевірки).
- TP1 Лева = `вхід ± 1,5 × ризик` (`office_lev_verdict._tp_from_rr`) — формула, а не рівень зі структури. Тому потенціал TP1 повністю визначається шириною стопа.

## Що показують дані
- Історичний прогін на реальних свічках (`docs/lev-replay-2026-09-29.md`): медіанний TP1 для альтів 1,4–2,0% проти порогу 3% → 86–100% карток відсікаються; для BTC/ETH 1,0–1,24% проти 1,2%.
- Production 2026-09-29 (логи worker): `SKHYNIX TP1 1,18% < 3%`, `VELVET 2,67% < 3%`; LSK пройшов (TP1 ≈ 3,7%) і став ACTIVE.
- What-if (те саме джерело, розділ 7): жоден варіант цілі не дав додатного очікування; ціль за найближчим H1-свінгом збиткова найменше (−0,30 R), при чинних правилах у моделі виконання угод 0 (TP1 = 1,5R і поріг RR ≥ 1,5 після проковзування несумісні).

## Як правило співвідноситься з типами угод
| Тип | Стоп → TP1 (TP1 = 1,5 × стоп) | Який стоп потрібен для 3% | Що виміряно |
|---|---|---|---|
| Скальп (M5/M15) | стоп менший за H1-стоп | ≈ 2% (для альтів) | у replay **не вимірювалось** (лише H1-сценарії); математично стоп 2% для скальпу нетиповий |
| Внутрішньоденна (H1) | медіанний стоп 0,67–1,34% → TP1 1,0–2,0% | ≈ 2% | виміряно (replay, 6 монет) |
| Свінг (H4/D1) | стоп ширший | ≈ 2% — досяжно | у replay **не вимірювалось** |

Висновок (виміряно лише для H1): 3% для альтів вимагає стопа ≈ 2%, тобто працює як **свінг-поріг**, застосований до всіх типів. Для внутрішньоденних він відсікає 86–100% карток. Для скальпу й свінгу потрібні окремі вимірювання на M5/M15 і H4/D1 (не робились).

## Варіанти (нічого не вмикається)
1. **Поріг за типом угоди**: скальп ≥ (4 × повна вартість угоди + запас), внутрішньоденна ~1,5–2%, свінг 3%. Потрібна погоджена таблиця й окремі тести.
2. **Поріг за волатильністю монети** (частка добового ATR), а не фіксований відсоток.
3. **Ціль зі структури** (найближчий рівень протилежної сторони), а потім перевірка порогу; без рівня — «плану немає».
4. Залишити 3% лише для свінгу; для інших типів мінімум від комісій/спреду й RR.
Обмеження доказів: один період (травень–серпень 2026), без підтвердження на M5, без BTC-контексту; жоден варіант не показав переваги — послаблення порогу **не доведене** даними.

## Потрібне рішення власниці
Чи вводити поріг за типом угоди (варіант 1/4) і які значення для скальпу та внутрішньоденних. До рішення пороги не змінюються.
