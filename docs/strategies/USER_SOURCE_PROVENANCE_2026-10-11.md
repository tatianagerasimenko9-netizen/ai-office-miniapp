## Обов'язковий формат кожного торгового правила
- `author` і `method`;
- `source_file` та `source_locator` (сторінка, скрин/кадр);
- `source_sha256` після фактичного зіставлення з файлом;
- `source_quote_or_fact` — фактично спостережувана авторська умова;
- `timeframe`, `sequence`, `invalidation`;
- `derived_thresholds` — лише числа, які прямо вказані в джерелі; інакше відокремити як `OUR_IMPLEMENTATION` / `ГІПОТЕЗА`;
- `verification_status`: `UNVERIFIED`, `SOURCE_MATCHED`, `TESTED_SHADOW`, `VALIDATED_OOS`;
- `deployment_scope`: без дозволу власниці тільки `SHADOW`/`PAPER`.

## Процедура
1. Для кожного факту створити адресний запис файл → автор → сторінка/кадр → спостережувана умова.
2. Не формувати штучні пороги або докази з прикладових графіків.
3. Сильна свічка **старшого** ТФ → відкат у її область → пошук молодшого входу; Fibonacci на **старшому** завершеному імпульсі: послідовність зі слів користувачки, але не математичні пороги автора.
4. Окремі сценарії Вайкоффа, Елліотта, SMC, рівнів Герчика: без «обов'язкового набору усіх індикаторів».
5. Для торгової інтеграції тільки підтверджені закриті свічки на момент рішення; далі shadow/paper, replay без lookahead, OOS. LIVE-гейти й реальні ордери без погодження не змінювати.
